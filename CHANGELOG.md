# Changelog

All notable changes to Praector are recorded here. README and focused documentation are intentionally release-version-neutral.

**Repository rule:** every repository change must update this file. Add work under `Unreleased` while it is in progress; when publishing a release, move those entries into the new version section and keep the newest release first.

## Unreleased

- Retired the **Python reference implementation** so the Go runtime (`cmd/` + `internal/`) is the sole implementation and source of truth. Deleted `src/praector/`, its pytest `tests/` suite, and the `scripts/` drivers (`parity_check.py`, `native_smoke.py`, `mcp_conformance.py`) plus the `pyproject.toml`/`MANIFEST.in` packaging via `git rm` (history-recoverable; no history rewrite and no branch-lifecycle change). Versioning is Go-only (`internal/praector/version.go`); `pyproject.toml` and `src/praector/__init__.py` no longer need hand-syncing each release. Two Python-coupled Go tests were removed: the src-comparing `TestEmbeddedSchemaAndPromptsMatchPythonReference` and the whole `TestMCPExternalConformanceOracle` (every assertion in it was the external `python3 scripts/mcp_conformance.py` exec). **Accepted coverage loss:** plain `go test ./...` no longer runs an out-of-process MCP client probe (the surviving `TestMCPOfficialClientInteroperability` skips unless `PRAECTOR_MCP_INSPECTOR` is set), and the `smoke-state` fresh-repo/isolated-`PRAECTOR_HOME` store smoke (`native_smoke.py`) is gone; the in-process Go suite plus `make smoke` remain the primary contract. `internal/praector/testdolt_test.go`'s self-contained fake-Dolt shim is untouched, so `python3` stays a go-test-time dependency by decision. Worker venv / `PYTHONDONTWRITEBYTECODE` language-hygiene prose and third-party "official SDK/reference implementation" research guidance are unchanged. Documentation across README/AGENTS/ROADMAP and the focused docs was swept to drop forward-looking references to the retired tree and to name the new docs-only embedded-asset drift convention; no new CI, Go tooling, or replacement tests were added.

- Corrected the MCP event-stream documentation's **`405` "does not advertise" rule** after verifying the push surface live against a real loopback listener. SSE negotiation (`internal/praector/mcp/transport.go:86-97`) accepts `text/event-stream` and **honors the `*/*` and `text/*` wildcards**, so a plain `curl` or browser `GET` — which sends `Accept: */*` when the header is not specified — **opens the stream**, and only a `GET` whose `Accept` explicitly excludes SSE receives the historical `405`. The docs previously stated the flat rule "a `GET` that does not advertise `text/event-stream` still receives 405", which holds for an explicitly non-SSE `Accept` but is wrong for the wildcard a default HTTP client sends, so anyone testing the documented request without the header would have concluded the documentation was broken. Documentation only: no refusal semantics changed, and the `MCP-Protocol-Version` header plus the loopback Host/Origin authority gate are still enforced before a single byte is written on every `GET` path, wildcard or not.

- Made the deterministic planning-policy **risk gates fire from the objective's detected risk category instead of only when the objective matches a mutation verb**, so the same real risk can no longer be gated or left ungated purely because of how it happens to be phrased. Previously `external_conformance_required`, `threat_model_required` (which feeds `plan_review_required`), and the integration-sensitive `critic_required` were computed as `(detected risk category) AND (objective matched a mutation verb)`, so a genuinely security- or integration-sensitive objective written as a noun phrase or in the passive voice — "The auth bypass in the token check requires correction", "The payment gateway contract versioning" — recorded the risk but skipped the very gate that risk justifies, while the identical request in the imperative ("Fix the auth bypass") was gated. Now those three gates plus `explore_required` are derived from the **category** alone (`external_conformance = protocol OR external_integration`, `threat_model = security OR network_boundary`, integration-sensitive critic from `external_contract OR external_integration OR protocol`, `explore = implementation OR any recorded risk`); genuinely implementation-ceremony signals — the `plan_review` `implementation and not trivial_docs` term, `delivery_policy.implementation_required`, and the research freshness triggers — **stay verb-based on purpose** so descriptive or trivial prose is not converted into plan-review theater, and `explore` is de-verbed to `implementation OR any risk` rather than unconditional. The destructive/migration detectors were widened **morphologically only** (inflectional forms of `delete`/`drop`/`purge` and `migrate`), deliberately **excluding** semantic synonyms (removal/cleanup/prune/wipe) as a documented known gap rather than silently broadening scope. The change is **forward-scoped by a single day-granularity guard**: collections created on or after `GateCoherenceCutoff` (`2026-11-12`) use the coherent category-derived gates, while collections created before it keep the historical verb-ANDed derivation at **every** enforcement seam — scheduler staging, the claim gate (`Store.planningGateAllowsClaimLocked`, whose collection read gained `created_at`), COMPLETE reconciliation, submit-time oracle strictness, and acceptance critic-stale — so no in-flight or already-`COMPLETE` work is retroactively re-gated or reopened; the guard fails **closed** to coherent when no collection row resolves, and it is a pure in-memory boolean derived from `created_at`, **not** a persisted marker column, policy-version field, or schema migration (the rejected `LegacyGateTraceabilityMarker` approach). For any objective where `implementation` is already true the coherent and legacy derivations are provably identical, so behavioral churn is confined to non-verb (noun/passive) objectives that record a risk category. The `PLANNING_POLICY_ENFORCED` event gained one **additive** `gate_derivation` field (`category` vs `verb_legacy`) recording which derivation applied, and `collection show` keeps reporting the resolved `planning_policy` as the audit surface. One pure classifier (`ClassifyPlanningPolicy` / `planning_policy.classify_planning_policy`) is unchanged in shape; every collection-derived Go seam (`cli.go`, `envelope.go`, `scheduler.go`, `service.go`, `store.go`) and its Python mirror (`db.py`, `cli.py`, `envelope.py`, `scheduler.py`) now route through a single `effectivePlanningPolicy`/`effective_planning_policy` helper so the surfaces cannot drift. Coverage: Go/Python phrasing-matrix and per-category coherence oracles, destructive known-gap, trivial-docs, cross-language parity vectors, and five per-seam forward-scope tests, plus the original Python behavioral contract; two existing current-news objective tests were intentionally widened (explore/gates now fire from the risk category while heavy critic/plan_review/implement stay absent). Docs updated in `docs/OPERATIONS.md`, `docs/AGENT_PROTOCOL.md`, `docs/ARCHITECTURE.md`, `docs/PROFILES.md`. Deferred (recorded in `docs/ROADMAP.md`): an operator override for pre-cutoff collections, destructive semantic synonyms, `\bserver\b`/`\bsecurity\b` calibration, a diff-derived post-write floor, persisted classification, a dedicated threat-model stage, and deleting the legacy verb branch.

- Made the `events` read surface **fail closed on unknown scope ids** so a mistyped target is an error instead of a successful empty page, aligning the one remaining read command that did not already follow the repository's fail-closed convention. Previously `praector events COL-DEADBEEF`, `praector events T-deadbeef`, and `praector events --project PRJ-nope` each exited `0` with no output, while every sibling read command (`collection show`, `graph`, `task show`, `result show`) exits `1` with `collection/task/project not found: <id>` for the same input — so an operator or agent paging the event log could not distinguish "this collection produced no events" from "I typed the id wrong", and a scripted `--since` walk over a mistyped scope terminated looking like a clean empty history. `Service.Events` now resolves every explicitly supplied scope id through the **existing store getters** (`GetProject`/`GetCollection`/`GetTask`) after cursor decoding and before `ListEvents`, propagating the getter error unchanged so the wording is byte-identical to the siblings for both the positional `TARGET` and the equivalent `--project`/`--collection` flag forms; no new not-found error-string literal was introduced. Resolution runs on the merged post-inference filters, so a `TARGET` and a flag naming one entity resolve exactly once, and two distinct unknown ids report a single error in the deterministic order project, then collection, then task. A contradictory `--project`/`--collection` pair is now an error naming both ids, implemented with the same fail-closed `Store.ProjectForCollection` resolver the memory/decision paths already use (not `projectForScope`, which short-circuits on the supplied project and never reads the collection). Project scope is **canonically resolved to the row id** (matching the `MemoryList`/`DecisionAdd` precedent), so a `--project` given as a project name or root path now returns that project's rows instead of a silently empty page. Explicitly unchanged: a valid scope whose page is genuinely empty is still a successful empty result with **no** `next_cursor` (so paging over a quiet scope still terminates cleanly), the all-empty no-target `projectForScope("","")` ambient fallback stays byte-identical, a malformed `--since` keeps error precedence over scope resolution, and `limit <= 0` coercion to `DefaultEventLimit`, `ORDER BY created_at, id`, the exclusive composite cursor, and the `next_cursor`-only-when-rows rule are untouched. The fix is confined to one function body: `commandHelp`→`serviceOps`→`mcpSurface` parity, `cli.go`, `help.go`, the MCP bridge, and the `mcp/` core are unchanged, so the MCP `praector_events` tool rides the existing `CallTool`→`isError: true` seam and reports the same message with the 2025-06-18 protocol revision untouched; `TestMCPCommandHelpParity`, `TestCommandHelpServiceParity`, and the skill CLI drift guard pass without edits, which is the proof no surface drifted. The SSE replay path calls `ListEvents` directly with internally registered stream filters rather than operator-supplied ids and is therefore unchanged by design. `events` is a **native-only** command already declared in `scripts/parity_check.py` `NATIVE_ONLY_COMMANDS`, so the Python reference tree mirrors nothing here by design rather than by accident. - Added the **server-initiated event stream** to the MCP surface: an enabled daemon answers a `GET /mcp` that advertises `Accept: text/event-stream` with a loopback-only SSE stream that carries **only** MCP `notifications/message` logging frames and **never a JSON-RPC response**, completing the push half of the work whose read half (the `events` command) shipped in the previous slice. Security is byte-for-byte identical to POST because the shared authority gate (loopback Host/Origin validation and the unconditional `MCP-Protocol-Version` header requirement) now runs **above** method dispatch, so a `GET` receives exactly the same 403/400 rejections as a `POST` before any stream is opened (a non-advertising `GET` still gets `405` and the POST surface is unchanged). The stream is **observation-only**: it launches no process, enqueues no task, and bypasses no policy/review/acceptance gate. **Protocol shape** follows MCP 2025-06-18 (**DEC-17fa4b4aff**, version-scoped, not a 2026-07-28 conformance claim): the domain-agnostic `internal/praector/mcp` core owns only the GET gate/Accept negotiation and the `logging/setLevel` method shape (advertised as a `logging` capability only when wiring supplies a provider), while **every stream, per-connection level, and Last-Event-ID replay decision lives in the new wiring-layer `mcp_sse.go`** — so the core stays stdlib and state-free. Level selection is FORK A (**DEC-5585465c21**): a per-connection effective level (`?level=` query parameter, validated against `mcp.ValidLoggingLevel`; an invalid value silently keeps the `info` default rather than failing) plus a real `logging/setLevel` with the full eight RFC-5424 levels and `-32602` on an invalid level, applied as a **best-effort broadcast across every active stream** because `mcp.LoggingProvider` carries no session-id/auth/correlation identity (the `sseHub.SetLevel` loop in `mcp_sse.go` iterates `h.streams` and stores the new rank on each); the broadcast is **exact for a single observer** and last-writer-wins across many concurrent subscribers, and per-connection `setLevel` is deferred roadmap work pending session identity — the 2025-06-18 spec leaves the scope unspecified, so this is a Praector implementation decision, not a spec mandate. **Emission** is FORK B (**DEC-48d49461e1**): all seven durable event writers (`Store.Event` plus the six inline `INSERT INTO events` sites) fan out through one shared emit seam whose publish is a **non-blocking enqueue** to a bounded side-channel drained by a single goroutine **outside** the Dolt file lock, so a stalled or disconnected client can at most drop and close its own stream and can never stall `Store.Event` or the write path. Slice 3 adds durable **status-transition events** at the `SetTaskStatus`/`SetCollectionStatus` boundaries (`TASK_*`/`COLLECTION_*`, no-op-guarded) with a fixed `event_type`→level map defaulting to `info` (**DEC-19f6a85625**), and Last-Event-ID replay reuses the `events` table and the `(created_at, id)` cursor seam from the previous slice (**DEC-81198d8940**), scoped to the connection. Deferred roadmap work (2026-07-28 `subscriptions/listen`/MRTR, `resources/subscribe`, per-entity resource URIs) is recorded in `ROADMAP.md`. Regression coverage exercises GET-security-equals-POST, the 405 preservation, the logging capability on/off, `logging/setLevel` conformance and `-32602`, the notification-only/no-response guarantee, live per-connection level filtering, status-transition events with no-op suppression, replay scoping and dedup, and stalled-client non-blocking fan-out; `commandHelp`→`serviceOps`→`mcpSurface` parity is untouched. Enablement, loopback-only binding, enqueue-only semantics, and all CLI output remain unchanged.

- Hardened **Git workspace identity** so the branch Praector integrates is provably the branch Praector assigned. Previously a worker was free to move HEAD or invent a branch and nothing compared the merged state against the durable assignment. **Read-only profiles** now capture a `WorkspaceSnapshot` (HEAD, attached branch, `git status --porcelain=v1 --untracked-files=all`, and the worktree's HEAD reflog) before the attempt and validate all four afterward. The reflog comparison catches a checkout-away-and-back that leaves HEAD, branch attachment, and status looking unchanged again at completion, and the violation detail is carried into the `READ_ONLY_CAPABILITY_RETRY` event.
